# R2.T6b — /reputacao/me canónico + flag gate + alias /reputation + RelatorioVocacional consumer

### Scope & Objective

Implementar o que torna verdes os 4 specs de R2.T6a. Inclui SSOT do schema em `@pdc/shared`, mount canónico `/reputacao/*` + alias temporário `/reputation/*`, gate de feature flag em `GET /me` (404 quando off), e substituir o consumo mock do `RelatorioVocacional` pelo endpoint real.

**In scope:**

| Ficheiro | Acção | Razão |
| --- | --- | --- |
| file:packages/shared/src/reputation.ts | NOVO | `ReputacaoTierSchema` (`BRONZE/PRATA/OURO/DIAMANTE`) + `ReputacaoBreakdownSchema` Zod completo (Approach §1.4) |
| file:packages/shared/src/index.ts | EXTEND | Re-export do schema novo |
| file:apps/api/src/routes/reputation.ts | MODIFY | `GET /me` verifica `featureFlagService.getEffectiveFlags().reputation_visible` no início → 404 se off, 200 + `getReputacaoBreakdown` validado contra schema; mount canónico `app.route('/reputacao', ...)` + alias `app.route('/reputation', ...)` |
| file:apps/api/src/modules/reputation/reputation.service.ts | MODIFY | `getReputacaoBreakdown` adiciona gate de flag (semântica acordada nos specs de T6a) |
| file:apps/api/src/index.ts | MODIFY | Mount adicional do alias `/reputation` (preservar `/reputacao` como canónico) |
| file:apps/web/src/lib/api/reputation.ts | MODIFY | Cliente continua a usar `/reputacao/*` (já está); validação opcional de payload contra `ReputacaoBreakdownSchema` |
| file:apps/web/src/features/simulacoes/RelatorioVocacional.tsx | MODIFY | Substituir `useQuery` para `/vocacional/perfil-premium` (mock fallback) por `useQuery(['reputacao','me'])` para `/reputacao/me`; tratar 404 com componente "Reputação ainda não disponível"; insights heurísticos usam `behavior_patterns` do perfil já existente OU placeholder `null` (sem inventar endpoint novo nesta wave — Approach §1.3 nota: "endpoint que vamos criar se não existir, OU usar dados já presentes em `behavior_patterns`") |

- Cache para `getReputacaoBreakdown` (Approach §4 Performance: continua sem cache)
- Mudanças no flag `REPUTATION_VISIBLE` em si (já existe em Strapi/feature-flag-service)

### Guardrails

- **Invariants §4**: `getReputacao` legacy continua a retornar 0 quando flag off (consumidores existentes inalterados); apenas `GET /me` muda semântica
- **SSOT em ****`@pdc/shared`**: schema **nunca** duplicado em BFF (Constitution §2 / Approach §4)
- **Alias é temporário** — comentário no `index.ts` deve dizer "TODO remove `/reputation` alias after frontend & integrations migrated to `/reputacao` (target: W3)"
- **Frontend e BFF mudam no mesmo PR** — semantic change intencional não pode ter window onde web espera 200 e BFF devolve 404 (Approach §1.2 Rollback)
- **`/vocacional/perfil-premium`** não inventar — se não existir, `RelatorioVocacional` simplesmente não chama (degradação graciosa explícita, não silenciosa) (Hotspot 8 Analysis)

- 4 specs de R2.T6a verdes (`npm test --workspaces -- --run reputation` exit zero)

- `getReputacao` legacy continua a retornar 0 quando flag off (W0-T6 verde)

- Commit message justifica alteração ao spec W0 (Approach §5.5)
